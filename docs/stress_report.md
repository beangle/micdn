# micdn HTTP 压测对比报告（2026-08-13 索引版）

目的：对比三次演进对四场景的吞吐影响——基线 `490a455`（每次请求同步 stat）→ `8ddfd47`（`sendFile` 必填调用方预取的 `FileInfo`、www `get()` 异步 stat 并复用）→ **发布期文件索引**（deploy 后构建段树索引，请求期存在性判定 0 stat）。

| 测量方法 | 各场景预热 5 轮后，3 轮各 10000 请求，取中位数；`performance` 调速器（负载核 ~4.4 GHz），无后台负载 |

| 场景 | URL | `490a455` | `8ddfd47` | 索引版 |

## 分析

1. **存在性判定归零是最坏路径的最大收益**：目录 → index.html 从"5 次 stat"到"0 stat"（索引内查 `index.html`），RPS +76.6%、平均延迟 4.36→2.83ms。发布期索引把"如何快速判断文件是否存在"从每次请求的 stat 前移为部署时的一次目录遍历。
2. **404 由回落转回升**：上一版 404 因异步 stat 通道开销回落 10%，索引版断链即 404（`isStaticAsset` 短路，0 stat），回升到 14.8k（+21.4% vs `8ddfd47`，+8.8% vs 基线）。
3. **文件命中受带宽/IO 制约**：138KB 响应约 1.9 GB/s，stat 减少后吞吐仍受读盘与网络限制（+15.4%），不如小响应场景明显。
4. **gzip 命中已降到 0 stat**：gzip 改为部署期预压缩，sidecar 大小随索引同趟登记（`gzSize` 挂源文件节点，`.gz` 不建节点），请求期一次 `find` 同时取得源与预压缩信息。表中 gzip 数字为索引版数据，本轮改动未重测。
5. **索引代价**：启动期每 doc/bundle 一次目录遍历（小规模毫秒级，输出汇总日志）；autodeploy 重建联动已实现；内存为轻量 `IndexedFileInfo`（约 32B/条，含 `gzSize`）+ 段树节点，10 万文件量级 6–8MB。
