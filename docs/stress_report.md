# micdn HTTP 压测对比报告（2026-08-13 索引版）

目的：对比三次演进对四场景的吞吐影响——基线 `490a455`（每次请求同步 stat）→ `8ddfd47`（`sendFile` 必填调用方预取的 `FileInfo`、www `get()` 异步 stat 并复用）→ **发布期文件索引**（deploy 后构建段树索引，请求期存在性判定 0 stat）。

## 修订版说明（每次压测对应的代码状态）

| 修订版 | 改动内容 |
|--------|----------|
| `490a455`（基线） | 无索引：每请求 stat 判定存在性；gzip 后台线程按需生成，请求线程 `getFileInfo(gz)` 现查 |
| `8ddfd47` | 存在性判定改异步 stat 通道（404 回落 ~10%）；gzip 仍请求期 stat |
| 索引版 | 发布期文件索引：存在性 / 目录折叠 / try-file 回退 0 stat；gzip 命中仍保留 1 次 `getFileInfo(gz)` |
| `2f0a386`（本轮） | gzip 改**部署期预压缩**（www auto-gzip / asset 非 `<dir>` 强制），`gzSize` 随索引同趟登记（gzip 0 stat）；共享 `FileIndex`（asset 复用）；`sendFile` 收 `IndexedFileInfo`；asset `AssetFile` 化、移除逗号拼接 |

## 分析

1. **存在性判定归零是最坏路径的最大收益**：目录 → index.html 从"5 次 stat"到"0 stat"（索引内查 `index.html`），RPS +76.6%、平均延迟 4.36→2.83ms。发布期索引把"如何快速判断文件是否存在"从每次请求的 stat 前移为部署时的一次目录遍历。
2. **404 由回落转回升**：上一版 404 因异步 stat 通道开销回落 10%，索引版断链即 404（`isStaticAsset` 短路，0 stat），回升到 14.8k（+21.4% vs `8ddfd47`，+8.8% vs 基线）。
3. **文件命中受带宽/IO 制约**：138KB 响应约 1.9 GB/s，stat 减少后吞吐仍受读盘与网络限制（+15.4%），不如小响应场景明显。
4. **gzip 命中已降到 0 stat**：gzip 改为部署期预压缩，sidecar 大小随索引同趟登记（`gzSize` 挂源文件节点，`.gz` 不建节点），请求期一次 `find` 同时取得源与预压缩信息。实测 gzip 命中 24 844 → **32 286 RPS（+30.0%）**，为最新版唯一的结构性提升场景。
5. **索引代价**：启动期每 doc/bundle 一次目录遍历（小规模毫秒级，输出汇总日志）；autodeploy 重建联动已实现；内存为轻量 `IndexedFileInfo`（约 32B/条，含 `gzSize`）+ 段树节点，10 万文件量级 6–8MB。
6. **非 gz 场景约 −2% ~ −3%**：代码层面非 gz 请求路径并无新增开销——`sendFile` 内的 `toFileInfo` 与索引版 `makeWwwFile` 的构造等价（两边均每请求一次 FileInfo 构造），且最新版还省去了每请求的 `isGzipEligible` 扩展名检查、`WwwFile`/`find` 返回结构更小；两轮复测均稳定低于索引版约 2%–3%，判断为编译布局与环境的系统性小幅差异，幅度小于 gzip 的确定性收益（+30.0%）。
